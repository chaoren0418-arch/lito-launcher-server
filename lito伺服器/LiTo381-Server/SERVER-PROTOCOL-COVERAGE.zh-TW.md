# LiTo 協定與功能範圍

流程摘要沿用共用來源部署；0.6.68 戰鬥／技能同源稽核見 [比較報告](docs/maintenance/combat-parity-0.6.68.md)。共用資源不代表完整戰鬥規則或外控一致。封包有 handler 不等於所有模式、目標與 UI 都完成實測。機器可讀的 `SERVER-PROTOCOL-COVERAGE.json` 因原始碼稽核測試仍會讀取而保留。原始完整 opcode 說明與 JSON 備份已保存於 `backups/history/layout-before-20261012.zip` 的 `server/SERVER-PROTOCOL-COVERAGE.*`。

## 現行主要流程

| 流程 | 目前接線／限制 |
| --- | --- |
| 選服／帳密 | 原生先選服再登入，來源 ID 固定 Repository 與登入埠；不同服同名帳號隔離 |
| 選角／頻道／大廳 | 同一客戶端程序返回及重新登入；角色頁返回帳密曾完成手動驗收 |
| 開房／戰鬥／結算 | 原生流程，結算 UI 與退出選單分流；每場戰績同步大廳及排行榜 |
| 商店／背包 | 購買與消耗在記憶體，離開／結算依場次生命週期清理商店物品；回大廳補發額度 |
| 技能／召喚物 | 含指定攻擊、治癒、輔助與負面／範圍流程；特效使用共用資源映射。完整技能組合仍需逐項驗收 |
| 動作／飛行特效 | 箭矢飛行曾完成手動驗收；單位外觀、動作與資源編號須與共用客戶端一致 |
| 倒數／道具說明 | 計時器與擴充說明由 LiTo 相容層配合；SQL 自訂文字保留，移除頁數尾行 |
| 管理指令 | `.item`、`.spawn` 路徑保留，依角色資料庫 GM 權限判定 |

## 後續驗收規則

新增或修正流程需比對：客戶端實際送包 → 來源與狀態檢查 → 遊戲效果 → 回包欄位與資源映射 → 返回／清理。錯誤與重送也須檢查，不能只因能解析封包便標記完成。

技能需覆蓋自己、玩家、NPC、召喚物及可攻擊性／隊伍規則；動作需在實際客戶端觀察。伺服器啟動測試僅證明資源及連線入口可用。[本次實際驗證](VALIDATION.md)；[歷史證據索引](docs/HISTORY.md)。
