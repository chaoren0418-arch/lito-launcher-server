# LiTo Modern 專用伺服器驗證候選

此候選的預設入口只啟動 Modern 伺服器，沒有舊版伺服器的預設設定回退。它與 LiToModern 玩家 EXE 配合；TW/LHZ 及原生 LiTo.bin 使用原專案，不由此候選啟動。這仍是開發驗證候選，不是完整遊戲交付。

## 啟動與停止

需要 Java 17，並保留 JAR 同層的 `lib` 目錄。以管理者配置的絕對路徑啟動：

```powershell
java -jar LiToModern-Server.jar --modern-config D:/伺服器設定/modern.properties --console
```

`--console` 明確開啟本機管理輸入；輸入 `status` 取得連線數，輸入 `stop` 正常關閉接收端與所屬工作。此模式的標準輸入 EOF 或讀取失敗也會正常停止，適合由有所有權的工具監管。不加 `--console` 時不讀標準輸入，可用正常 JVM 終止訊號觸發既有關閉流程。這些是管理程序的本機指令，不是玩家聊天或網路管理端點。

不帶參數、錯誤參數、缺失／錯誤 Modern 設定均拒絕啟動，絕不改讀 `config/server.properties`。`--version` 單獨使用只列出程式能力，不讀配置、不連資料庫、不開遊戲 listener。版本能力不代表配置已啟用所有玩法或角色治癒。

## 配置與資料邊界

本包不附可直接登入的帳密、私人金鑰、來源資料庫或自動寫入來源的腳本。管理者須明確提供 TLS 身份、唯讀來源、各來源顯示名稱與編號、共享 Lineage 資源、已驗證地圖設定、裝備狀態路徑及結算庫權限；不存在通用範例可以替代這些實際配置。

玩家 profile 應使用 schema2／modern_v47，正確配置同一伺服器端點與公開 CA 信任。角色治癒需雙端明確啟用 `player_healing_v1` 及相應來源／地圖資格；不相容時應拒絕，不得停用 TLS 或回退旧協定。

本包的 `db` 只提供 Modern 專用結算與世界規則的建表來源；不會自動執行。請先審核庫名與權限，勿直接套用玩家來源庫。既有角色、物品與技能來源維持唯讀；Modern 的結算與裝備狀態各自使用明確的目的地。

## 完整性與驗收範圍

`SHA256.json` 列出包內檔案與建置來源摘要。本地收據用於辨識陳舊／混用成品，不是數位簽章。JAR 包含共用伺服器實作類別；分離的是 Modern 專用入口及配置，不宣稱已裁切全部舊類別。

即使隔離資料库、TLS、共享資源與打包 JAR 流程測試通過，仍不能據此宣稱玩家 EXE 的所有按鈕、真正視窗、長時間操作及所有技能／地圖已完成。部署到正式來源前，須完成成套配置與這些驗收；不要覆蓋正在使用的舊伺服器。
