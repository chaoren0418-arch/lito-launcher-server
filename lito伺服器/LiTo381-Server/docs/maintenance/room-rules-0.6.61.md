# 0.6.61 測試房與開戰規則

2026-10-14。正式 JAR 基底為 0.6.60；未更換客戶端 DLL、LiTo.bin 或共用資源。

## 設定

先由資料庫管理帳號執行 `db/lito_room_policy.sql`。正式執行帳號仍只有此表的 SELECT 權限；伺服器不自行建表或覆蓋設定。既有 `lito_battle_rule` 數值未修改。

`380_lito.lito_room_policy` 固定一列，`policy_id=1`：

| 欄位 | 目前值 | 用途 |
| --- | --- | --- |
| `test_room_enabled` | 1 | 各頻道保留 Local Lobby；0 則不自動建立 |
| `test_bot_enabled` | 1 | Local Lobby 死亡競賽只有一位真人時加入 ArenaBot；0 則不加入 |

修改後重啟。缺表、缺列或無效值會拒絕啟動並指出資料表；不默默降級成舊版規則。房間是否為測試房依伺服器的 defaultRoomId 判斷，自建同名房間無法取得測試例外。

## 開戰與結算

- Local Lobby 死亡競賽單人測試：真人選紅隊，ArenaBot 在藍隊；真人準備後可開始。兩位真人時由真人對戰、不加入假人；離開後回到單人時恢復假人名單。
- Local Lobby 不論模式或真人數都不保存勝敗，不產生結算收據；仍走正常結算畫面、返回與清理流程。判定在開戰時固定，避免斷線、清房或換角後遺失。
- 玩家自建房不自動加入假人。真人數採 `lito_battle_rule.minimum_players`，觀戰者及 GM 虛擬名單不計入。
- 隊伍模式至少兩位真人且紅藍兩隊皆有人；「人數一致」要求雙方相等。攻城保留 `native.siege.roster.enforced` 的每隊 15～50 人限制。
- 所有參戰真人都必須準備。開始倒數、倒數到期與人數／隊伍／準備異動時重驗；條件失效取消倒數。拒絕開始會發送中文系統訊息。
- 時間競賽目前 SQL 下限為 1，因此仍可單人開始；其餘目前下限為 2，攻城為 30。這是各模式的資料庫規則。
- 普通玩家房沿用 0.6.60 的斷線結算與勝敗去重保存流程。

## 建置與驗證

`tools/room-rules/build.py` 從固定 SHA 的 0.6.60 核心施作窄幅修補；同步修改 Java 來源，不使用有其他開發內容的全專案重建核心覆蓋正式版。

已通過：

1. `test.py`：實際加密 socket 封包、假人房間名單與世界 bootstrap、HP、真人退出後恢復假人、測試結算不記錄、返回清理、同名房不能繞過、單人拒絕及提示、同隊拒絕、換隊取消倒數、雙人開戰與無假人洩漏。
2. 測試房關閉／假人關閉、其他模式不加入假人；正式 SQL 執行帳號讀取新表。
3. 0.6.60 `FlowRegression`：隊員斷線繼續、整隊離開判負、收件 socket 關閉前保存雙方結果、晚到斷線不覆寫勝方、全斷線作廢。
4. 正式 SQL 啟動及 READY、端點驗證、owned cleanup；登入器完整雜湊驗證。

紀錄位於 `tools/room-rules/evidence.json`、`build/test.log`、`build/durable-flow.log`。客戶端畫面仍待使用者手動測試。0.6.60 基準備份不變；此次新增的控制表不影響回退舊核心。
