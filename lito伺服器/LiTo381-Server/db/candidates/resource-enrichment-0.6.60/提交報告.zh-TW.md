## 5. 驗證、SQL 與實際執行範圍

本次唯讀 SELECT 只查 `VERSION()` 與共用 weapon／armor／etcitem／skills／npc 的 ID，未查帳號、角色、玩家物品或結算內容。現場版本為 **MySQL 5.5.22**；IDs 是本次 snapshot，LiTo 五表逐列一致則引用原先2026-10-13審查，沒有冒稱本次重新取得其即時值。SELECT 時點存於 static-reference-select.json。

兩份 SQL 使用 `lito_cand_*` 隔離候選表、InnoDB、MySQL5.5的 utf8 與 LONGTEXT；沒有 JSON 型別、CHECK、generated column、utf8mb4新版 collation 等依賴。只包含建表與候選 INSERT，沒有 DROP、TRUNCATE、DELETE、UPDATE、REPLACE、ALTER、CREATE DATABASE 或正式表資料 INSERT。沒有指定 USE；未來匯入前必須另行決定管理庫、權限、遷移與載入方式。表存在時 CREATE／重複主鍵應報錯，沒有用覆寫語句掩蓋衝突；DDL 也不受後續 DML transaction 回滾保證。

獨立 verify_package.py 將每筆 INSERT 的字串／NULL／整數重新詞法解析，與 JSON 逐欄比較，檢查整數範圍、VARCHAR 長度、utf8三位元組相容性、重複鍵、原生地形參照、每個 SQL 欄位來源覆蓋與來源雜湊。**這是離線詞法、資料與範圍驗證，不是 MySQL server parser／匯入驗證。SQL 沒有實際執行，也沒有建立測試資料庫。** 精確列數與檢查項目見 verification-result.json；全部源檔於提取結束與獨立驗證時再次核對 SHA-256。

兩個核心固定值：

- `0-客戶端/LiTo.bin`：`ce6ee68ada8fd37e6c096b1a27e46cb6888f1179f85defb5007ac60287360292`。
- 正式 `LiTo381-SharedResources-candidate.jar`：`bbc59308c43df89ee5029d3b3c802be8ad55fee65c41faca99a76912dd5dce43`。

原生分析 contract 的 PE／ASM 路徑已檢查存在與原雜湊相符，結果存於 evidence-boundaries.json。native-static-locators.json 保留相關 VA／解析器定位，**VA 不當成磁碟 bin offset**，本次沒有重做反組譯。檔案隨正式 JAR 提供不代表大廳流程啟用；工作原始碼也不代表已發布。

本次沒有資料庫寫入、玩家資料修改、正式 JAR／DLL／設定檔變更、候選 SQL 匯入、程式接線、遊戲或伺服器啟動／重啟。所有新增產檔限於本成果目錄；原始資源、基準備份與現有 SQL 保持唯讀。未複製整套資源或完整資料庫。
